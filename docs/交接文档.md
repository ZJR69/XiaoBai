## 1. 项目是什么

「小白」是用户（张菊蓉，GitHub: ZJR69）的**本地个人智能体工作台**，管理日常学习、工作和生活。核心产品哲学（两份原始文档 `docs/小白PRD.md`、`docs/交互设计文档.md` 定案，实现已全部对齐）：

1. **对话重陈列轻**：对话流是主路径，各视图只是快捷方式
2. **防污染铁律（最高优先级）**：所有入库修改必须经用户裁决（同意/修改后同意/丢弃），自动流程只监听不修改，全量留痕可审计（`agent_suggestions` 表）
3. **三层记忆**：core.md 底座记忆 → 进行中的事索引 → 实体索引 → 知识库，关键词命中自动展开详情
4. **本地优先**：SQLite + 本地 markdown wiki，DeepSeek API 是唯一外部依赖（无 key 时优雅降级，核心功能不依赖 LLM）
5. **小白永不主动催用户**（不催闪记、不催消化，只投放区文件超 14 天发一次坟场通知——这是用户明确裁决过的边界）

## 2. 技术架构与运行

```
位置        d:\0AboutMe\xiaobai
前端        React 18 + Vite，6 视图，端口 5173（vite 代理 /api → 8000）
后端        FastAPI + SQLite，端口 8000，14 个 router（backend/app/routers/）
数据库      storage/xiaobai.db（表结构见 backend/app/database.py DDL）
wiki        storage/wiki/*.md（core.md / entities/ / topics/ / sources/ / index.md / log.md）
投放区      storage/raw/dropzone/（用户丢文件进来消化）
LLM         DeepSeek API（backend/.env 配 DEEPSEEK_API_KEY，key 模板在 .env.example）
调度器      scheduler.py 后台 daemon 线程 30s tick（提醒/截止/日程预告/坟场/每周lint）
通信        前端轮询（通知/dropzone 15s，跨天检查 60s），对话用 SSE 流式
启动        双根目录 start.bat（幂等：端口占用则跳过；netstat 检测）
```

**关键点**：改前端代码 vite 热更新自动生效；**改后端代码必须重启 uvicorn 才生效**（用户曾经因此遇到 404）。

## 4. 数据模型要点（易错处）

- `chat_sessions`（id/title/parent_id/created_at/updated_at）：多会话，parent_id 非空=分支会话
- `chat_messages.session_id`：NULL = 天级消息（☀早报/🌙复盘/⏰重要通知），属于某天不属于会话；查看今天活跃的会话时按时间序合并展示
- **存量迁移**（database.py init_db）：旧消息按日期自动归会话，排除 ☀🌙⏰ 三种前缀。注意：DDL 里不能放依赖 ALTER 补列的索引（`idx_chat_messages_session` 在 init_db 里建，放 DDL 会崩——踩过的坑）
- 间隔重现：倍增 1/3/6/12/24/30 封顶（database.py DDL 注释写 1/3/7/14/30 是历史遗留，以实现为准）
- 教学周计算：学年 9 月起（1-8 月归上一学年），9 月 1 日所在周的周一 = 第 1 周

## 5. 已完成功能（截至本文档更新）

**M1-M6 全部完成**：闪记/任务/骨架、界面重构/wiki 消化/三层记忆、进展日志/打包器、日程表/早晚简报/复盘阈值自校准、间隔重现/坟场、生活提醒调度。

**对话流三件套**（产品主线闭环）：
- 操作卡：LLM 回复末尾 `<<<ACTION>>>{json}<<<END>>>` → 后端剥离 → 前端确认卡（执行/忽略/撤销，pre-image 快照恢复旧值），支持建任务/改任务/勾完成/加提醒
- 实体锚点：`/api/anchors` 返回真实库条目，对话中匹配渲染为可点击（防幻觉：不能引用不存在的条目）
- 闪记闭环：提案入库时自动比对闪记池，覆盖到的自动 confirmed

**多会话模式**（最新完成）：侧边会话面板（点空白收回）、按活跃排序、增删、进入继续对话、任意消息开分支（用户消息分支点=重新生成语义）。流式输出带光标，`<<<ACTION>>>` 不进正文。

**其余**：统一搜索、wiki 编辑+体检（孤儿页/core 超 80 行/重复实体）、每周一自动 lint 通知、修改后同意、被拒提案留痕、start.bat 启动器。

## 7. 工作约定（用户明确要求过的，必须遵守）

- **全程中文**交流；代码注释也用中文
- 改代码前先讲方案，重大架构/算法决策必须咨询用户，不能自作主张
- 每轮修改后：后端 `python -m py_compile`、前端 `npm run build`、起临时端口冒烟测试（如 8767/8768），**测试脚本用完即删，测试数据精确清理**（用标记词如「冒烟xxx」便于 LIKE 清理，注意助手回复可能不含标记词，需按 session_id/精确 id 清）
- 预计几十分钟的测试要先告知用户
- 提交信息用 `git commit -m '标题' -m '详情'` 多段式，中文，说清 why
- push 需代理：`git -c http.proxy=http://127.0.0.1:7897 push`（代理地址可能变，失败时让用户开代理）
- git 输出的 LF/CRLF warning 无害，忽略
- Windows 环境，终端是 PowerShell（python -c 内嵌双引号会踩转义坑，复杂逻辑写临时 .py 文件）
- 时区：一切日期计算用**本地时间**（`datetime.now()` / 前端 `new Date()` 手动拼），不要 `toISOString()`（UTC 会让东八区凌晨错一天——踩过的坑）
