## 1. 项目是什么

「小白」是用户（张菊蓉，GitHub: ZJR69）的**本地个人智能体工作台**，管理日常学习、工作和生活。核心产品哲学（两份原始文档 `docs/小白PRD.md`、`docs/交互设计文档.md` 定案，实现已全部对齐）：

1. **对话重陈列轻**：对话流是主路径，各视图只是快捷方式
2. **防污染铁律（分层版，2026-09-26 定案）**：对标 ChatGPT/Claude 记忆哲学——**进展记录自动入库 + 全程透明 + 事后可管理**（对话提到事项即后台提取五分类日志挂账，页面可见可删可改，agent_suggestions 留痕 user_action='auto'）；**结构化操作（建任务/提醒/日程/资源）仍必须用户裁决**（操作卡确认执行可撤销）。自动流程只监听对话不弹窗不打断，全量留痕可审计
3. **三层记忆**：core.md 底座记忆 → 进行中的事索引 → 实体索引 → 资源索引（链接/资料地址），关键词命中自动展开详情
4. **本地优先**：SQLite + 本地 markdown wiki，DeepSeek API 是唯一外部依赖（无 key 时优雅降级，核心功能不依赖 LLM）
5. **小白永不主动催用户**（不催闪记、不催消化——这是用户明确裁决过的边界；坟场通知曾为例外，2026-09-24 随 wiki 阶段四下线）

## 4. 数据模型要点（易错处）

- `chat_sessions`（id/title/parent_id/created_at/updated_at）：多会话，parent_id 非空=分支会话
- `projects.parent_id`（2026-09-26 二级事项）：**封顶两级**（父必须存在且为一级；有一级子项的事务不能再挂靠；自挂 400）；存量迁移=「课内学习」描述里 9 门课自动拆二级（settings 键 projects_course_split 幂等）；CATEGORIES 补 course（旧版校验漏了它，建课程类 400 的存量 bug 已修）
- **自动记忆**（chat.py `_auto_memory`，2026-09-26）：对话流结束/`/api/chat` 返回后，后台线程提取进展（命中门控：消息含任一 active 事项名才跑，否则零 LLM 开销）→ 五分类日志（background/decision/status/next_step/note）source='agent' 挂对应事项 + core/entity 写盘 + 闪记闭环（覆盖到的 pending 闪记自动 confirmed）+ agent_suggestions 留痕 user_action='auto'；DeepSeek 延迟约 1-2 分钟，后台跑不阻塞对话；提取失败静默放弃。**防双胞（2026-10-09）**：收 actions 参数，操作卡 create_task 已带 next_step 的事务跳过 next_step 提取
- **待办⇄事务联动**（2026-10-09 定案）：`progress_logs.done_at` 列（幂等迁移）+ `task_id` 接线——create_task 带 patch.next_step 时同步写一条关联日志；complete_task → 关联日志 done_at 置位落地（页面消失数据留痕，undo 清回 NULL）；delete_log 提供全删选择（整行快照可撤销）。备注/下一步可独立存在也可关联存在，关联时机由小白智能判断
- **课表可见可改**（2026-10-09）：学期课表常驻注入 `_build_context`（weekday 分组+单双周标注+过期槽位跳过，不再靠日期词触发）；slot 三 op（create/update/delete）+ update_event 补齐课表修改能力
- **操作卡 op 全集（22 个）**：create_task / update_task / complete_task / create_reminder / update_reminder / create_event / update_event / delete_event / create_slot / update_slot / delete_slot / create_link / create_project / complete_project / delete_task / delete_reminder / delete_link / delete_project / delete_log / create_filter / delete_filter / resolve_inbox——全部用户裁决执行 + pre-image 快照可撤销
- **上下文注入面（`_build_context`，2026-10-12 对齐操作面后全量）**：today_line + core.md + 事务索引 + 未完成任务（含窗口/rrule/repeat_mode）+ 学期课表常驻（**含生效区间 + 已结束槽位**——已结束不隐藏，「课程丢失」类报障的诊断锚点）+ 近期一次性日程 + **重复日程系列（带 rrule 原文，明示删/改作用于整个系列）** + 实体索引 + 生活提醒（带触发描述）+ **闪记原文**（不再只有计数）+ 已存筛选 + 资源索引树。**原则：模型能做的事，上下文里必须能看见；看不见的就在提示词里声明不能做**——本轮四个高危 bug（草稿动线断裂/幻觉 op/系列误删/课表截断盲诊）同出一个病根「注入面与操作面不对齐」
- **注入升级**（chat.py `_expand_mentions`/`_ongoing_lines`）：事项索引树形化（一级+二级缩进）；子事项名命中展开（带父归属「（属于《X》）」）；一级命中附子事项概览+关联实体页（实体页内容含事项名 → 人和事挂上）；日志取最近 10 条（叙述素材）
- `chat_messages.session_id`：NULL = 天级消息（☀早报/🌙复盘/⏰重要通知），属于某天不属于会话；查看今天活跃的会话时按时间序合并展示
- **存量迁移**（database.py init_db）：旧消息按日期自动归会话，排除 ☀🌙⏰ 三种前缀。注意：DDL 里不能放依赖 ALTER 补列的索引（`idx_chat_messages_session`、`idx_links_parent` 都在 init_db 里建，放 DDL 会崩——踩过两次的坑）
- `links.parent_id`（2026-09-26 树化）：kind 增 'group'（话题索引节点，无 target，可无限嵌套），parent_id 指向父 group（NULL=根级）；父校验=存在且为 group + 沿 parent 链防环，非空 group 禁删；存量迁移=旧 category 自动转一级话题（settings 键 links_tree_migrated 幂等，「其他」/空分组留根级）
- ~~间隔重现~~：已随阶段四下线（spaced_reviews 表数据保留，不再读写；原机制：首现 1 天后倍增 3/6/12/24，30 封顶）
- 教学周计算：学年 9 月起（1-8 月归上一学年），9 月 1 日所在周的周一 = 第 1 周
- `schedule_events.rrule`（阶段三）：iCalendar RRULE 原语，NULL=一次性，系列行 date=首次日期（dtstart）；查询时展开不落库，唯一展开点 scheduler.py `slots_for_date`（week/today/预告/早报全走它）。**坑**：实例都在 00:00，`dateutil between()` 闭区间会把次日 0 点实例算进当天——必须半开窗口 `[day0, 次日0点-1微秒]`
