## 0. 核心理念

**小白是智能体，不是任务管理器。**

用户否决过的方向（反面教材，勿回潮）：
- ❌ 待办 App 的 plus 版（顶部速记 + 平铺任务列表）
- ❌ 仪表盘/卡片墙作为首页（陈列感过重，助手感缺失）
- ❌ 项目卡片 + 状态灯信号那一套（待办感太强，只剩事务丢了知识/同步）

用户的核心诉求：**「对话重、陈列轻」的助手感 + 「全局但不一股脑」的巡视能力。**

## 1. 双页结构

### 1.1 主页面 = 对话流（默认页）

小白的主场。所有日常交互发生在这里。

**对话内容构成**：
- 小白主动消息：早间简报（叙述式，非仪表盘）、晚间复盘、风险提醒
- 用户自由对话：像网页版 LLM，但它拥有用户全部项目记忆——**零同步成本**是核心价值
- 操作指令：对话驱动（「把 X 推到周五」→ 它执行 → 回确认卡）

**对话流中的信息组织**：
- 小白叙述中提到的项目/任务/知识页，全部是**可点击的实体锚点**（hover 显示条目摘要，点击跳转对应视图）
- 它说的每件事关联真实库条目，有据可查——**这是防 AI 幻觉的机制**
- 需要展示结构化信息时（如消化一篇资料、排本周计划），在对话流中铺开**内嵌卡片**，而不是跳走页面

**常驻元素**：顶部一条极简状态栏（今日剩余事项数 + 待处理提醒数 + 收件箱数），一眼瞥完不占注意力。

### 1.2 副页面 = 陈列区（巡视）

侧导航切换，主区永远显示内容，与对话一键互切不叠窗。

侧导航项（用户确认的全集）：

| 视图 | 内容 | 组织轴 |
|---|---|---|
| **项目全景** | 每个项目：状态/下一步/最近动态/关联任务 | 项目 |
| **时间轴** | 日程 + 截止任务排布；**粒度灵活**（用户明确：有的项目以年计，有的以天/小时计），今日/本周/月/学期可缩放 | 时间 |
| **知识库** | wiki 页列表 + Git 式状态标注（已归档/未归档/有修改），改动高亮，可点入阅读 | 主题/实体 |
| **生活角** | 生活杂务、习惯、提醒，与正事不混排但一眼可见 | 类别 |
| **闪记** | 哑捕获池：勾选若干条召唤小白对话式处理 | 堆积序 |

## 2. 四条核心机制

### 2.1 实体锚定（防幻觉）

- 对话中出现的项目名/任务/日程/知识页 → 自动识别为可点击锚点
- 点击跳转：项目→项目全景、知识→知识库、任务→时间轴定位
- 锚点数据来自真实库，小白不能引用不存在的条目

### 2.2 记忆同步（防污染）— 用户修正后的定稿方案

**对话过程中绝不打断**。共识入库的流程：

1. 对话进行中，小白**不弹任何提案**，保持对话流纯净
2. 用户觉得对话差不多了，点击**「回顾对话」按钮**（对话输入框旁常驻）
3. 小白回顾整段对话，生成**提案清单**（batch）：
   - 提取的新共识、新结论、待办、需更新的条目，逐条列出
   - 每条带：来源对话摘录 + 拟入库动作（新增/修改/关联）
   - 用户逐条裁决：同意 / 修改后同意 / 丢弃
4. 裁决完成后一次性入库，对话流里留下一条汇总回执

**例外——小事即时确认**：改日期、勾完成、删条目这类低风险小操作，小白执行后直接回一张小确认卡（撤销按钮），不进提案流程。

**原则（用户原话）**：所有入库信息都需要我的同意，需要经过我的决策。不允许记忆随意修改造成污染。

### 2.3 知识库 Git 化（工作流式，弱对话）

- wiki 条目/文件带状态：**已归档（clean）/ 未归档（untracked）/ 有修改（modified）**
- 用户在知识库视图里阅读、编辑（可直接改 markdown）
- 小白**检测到**未归档/有修改的积累后，不立即打扰；用户说「整理」或主动点击时，它统一审阅这批变更 → 生成整理提案 → 同意后归档入库 + 更新 index/log
- 类似 git 的 working directory → staging → commit 心智模型

### 2.4 对话驱动操作

- 所有事务操作优先对话：「第二件推迟到周五」→ 小白改 → 确认卡
- 视图内保留直接操作作为快捷方式（巡视时顺手勾完成），但不是主路径

### 2.5 闪记（哑捕获池，2026-09-18 定案）

- ~~快捷键 Ctrl+Shift+X 唤起迷你输入框~~（2026-09-19 用户裁决移除：改为闪记视图顶部常驻输入框，5 秒记完即走，不打扰、不要求分类）
- 落入闪记池（原「收件箱」重设计：独立分拣 UI 取消，概念降级为队列）
- **处理是召唤式的**：用户在闪记视图勾选若干条 →「去对话处理」→ 对话流自动发起 → 小白看懂则提案（走提案裁决），看不懂则提问、用户解释
- 随叫随到：小白**永不主动催**（用户定案，放弃超期自动清理）

### 2.6 知识库视图（2026-09-19 定案，经 5 轮问答裁决）

**结构**：三 tab 主次分明（延续已裁决的「三 tab 常驻」）——**知识**（主 tab，默认着陆，融合方案首屏）/ **原料区**（副，处理台）/ **体检**（副，周报+整理台）。

**首屏 = 融合方案**（原型 kb-firstscreen-options.html 方案 A）：
- 顶条：搜索框（输入即时下拉 wiki 命中；回车/「问小白」带问题跳对话，复用 chatSeed）｜待消化 N｜待归档 M｜本周新增 K 页
- 左区：**主题索引** = index.md 两级结构渲染。`## topics` 下设 `### 子主题`，每个子主题一张分类卡片（消化引擎写页时维护分组，未分组落「未分类」子节由 lint 兜底提醒；entities/sources 保持平铺各一张卡片）。卡片手风琴原地展开（页多限高滚动），页 chip 点击进阅读页
- 右栏：**最近动态 feed** = `wiki_events` 表驱动（kind 按来源分类着色：ingest 消化 / settle 对话沉淀 / edit 手动编辑 / raw_modified 原料变动 / lint 体检；CRUD 信息写进 summary），条目内页面名渲染为可点链接跳阅读页
- 三 chip 点击：待消化→原料区 tab；待归档→下拉面板；本周新增仅展示

**阅读页**（取代原阅读模态）：知识 tab 内二级视图，全宽 markdown 渲染。
- **历史栈契约**：进入=push，后退=pop，栈空回首屏；所有入口（feed/索引/双链/搜索/待归档面板）行为一致——防交互 bug 核心
- **双链** `[[页面标题]]`：全库标题匹配。唯一直跳；多匹配弹选择；零匹配渲染灰死链，且自动汇入 lint「缺页概念」检查（顺带兑现 schema 手册承诺过的检查项）
- 阅读/编辑/归档全产品仅此一处

**待归档工作流**（本节取代 2.3 的「整理提案」流程——该流程从未实现，废止）：
- Git 三状态语义不变：clean=认可基线 / untracked=新写未审 / modified=认可后又变
- chip 语义为「**待归档 N**」= untracked+modified 合并计数（PRD 原型的「有修改 1」系原型简化；新页最需要审阅，只算 modified 会漏）
- 双动线：A 跟事件走（feed 条目→页面链接→阅读页归档，趁热审阅）；B chip 兜底（下拉面板全量清单：色点+页名+来源+时间，通知面板同款点外收回，保证旧遗留不被时间流冲掉）
- **归档存内容快照**（wiki_pages.archived_content），modified 页阅读时显示与快照的行级 diff（绿增红删）——兑现 schema 铁律 3「写入展示 diff」。存量页无快照提示「下次归档后可对比」，自然迁移
- 批量「全部归档」= 面板次级按钮+确认弹窗（批级裁决仍由用户主动发起，不违反防污染铁律）

**原料区 tab**：现状交互保留（扫描+勾选+批量消化）；消化完成 → 知识 tab 首屏数据重拉，feed 出现新条目。
**体检 tab**：现有 4 项检查 + 新增「缺页概念」（双链死链收集）+「引用信号 Top/Bottom」区块（FR-2.9；本期埋点只取可靠三类：锚点点击/context-pack 引用/间隔重现展示，不做回复文本自动检测）。

**数据 pipeline**（写入侧三件套，全部写路径统一遵守）：任何 wiki 变更动作 = 写 wiki 文件 + 记 log.md + 插 wiki_events（机读：kind/summary/paths JSON/created_at）；**归档例外**——只更新 wiki_pages（哈希+快照+时间），不产生 event（归档是基线元操作，非内容变化，进 feed 会稀释）。

## 3. 小白人设（用户明确）

- **不预设性别**（用户纠错记录：勿用「她/他」，产品文案用「小白」或「它」）
- 聪明、正常大模型默认语气，**不做刻意的角色扮演设计**
- 防焦虑不是靠语气卖萌，而是靠信息组织（做减法、适时、不轰炸）
